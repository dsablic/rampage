# Phase 4.1 benchmark reports

Part of the [accuracy benchmarks](../benchmarks.md).

## Phase 4.1 Raw Project processor roster

The [roster measurement](phase4-1-roster-2026-10-21.json) opens every one of the sixteen Sleigh
roster fixtures as an ordinary Raw `Project` (`Binary::from_raw_code`), not through the explicit-window path.
It is generated by `rampage-eval processor-roster` and is the `processor_roster` section of
`rampage-eval run --suite parity`. "Manual" seeds every truth entry, so it measures retention and exact byte
extents, not discovery; "call-only" seeds only the base entry, so callees count only when reached by
followed calls. Every miss is attributed to the decode gate that stopped analysis; none is unexplained.

**Totals: manual 32/32 entries retained, 23/32 exact extents; call-only 27/32 retained, 20/32 exact.**
Only MSP430 and AVR8 decompile (they have reviewed C models); the other fourteen refuse with
`no reviewed C model for <language id>`. Ghidra column: functions Ghidra created from the same manual seeds.

## Phase 4.1 explicit-window checkpoint

The [frozen three-profile MCP measurement](phase4-1-sleigh-2026-10-19.json) recovers all six
manual/independent-Java function entries and exact byte extents using caller-only seeds. Its eleven MCP
requests comprise five successful observations and six expected rejections, with unchanged fixture files
and no sidecars. AVR retains byte target `0x210` versus word target `0x108`; CPSE and DES are valid
instructions with explicit conservative unknown-flow gates rather than invalid-opcode claims.

All 259 embedded specification files were bound before/after build and measurement. The parser bounds fix
has a scoped ASan/UBSan check, not whole-library sanitizer coverage. The full API checkpoint passed 749
tests with nine ignored. These checks overlap and are not summed into independent investigations.

All sixteen roadmap families have audited resource closures. Only MSP430, AVR8 and 6502 have this native
window/discovery checkpoint; the additional thirteen have independent Java oracle records, not native
acceptance. Ordinary `Project` fallback, architecture/width integration and ABI-checked decompilation are not
done. **Phase 4.1 is not complete**, and this checkpoint changes no live/N, recall or efficiency gate.
